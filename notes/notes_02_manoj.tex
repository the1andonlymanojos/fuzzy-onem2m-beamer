\say{``Thanks Raj. Before the clever part, let me show you the plumbing: what oneM2M is, and where the controller sits.''}

\slide{onem2m}{$\sim$40 s}{oneM2M in one slide: bullets on the left, resource tree CSE $\rightarrow$ AE $\rightarrow$ CNT $\rightarrow$ CIN on the right.}
\say{``oneM2M is a global standard for IoT middleware. It sits between devices and applications so that devices from different vendors, speaking different protocols, HTTP, MQTT or CoAP, all look the same to the app.''}
\say{``Everything is a resource in a tree. At the top is the CSE, the oneM2M server. Applications register as AEs. Each AE has containers, and every sensor reading is a contentInstance, in this paper a 1\,KB reading. Devices just send CREATE requests to add readings.''}
\say{``The server used here is Mobius, an open-source oneM2M implementation. The link between two oneM2M servers, say edge and cloud, is called Mcc. That is the link offloaded traffic travels over.''}

\slide{fig1}{$\sim$40 s}{The paper's own architecture figure, with five numbered steps.}
\say{``This is the paper's Figure 1. Top: devices, a thermometer, a factory, a wind turbine, feeding data injectors. Middle: the edge oneM2M platform with its protocol bindings, the CSE in red, the application entities and their containers.''}
\say{``Bottom: the self-management loop, Monitor, Analyzer, Planner, Executor, and a Knowledge base, plus the Fuzzy Logic Controller. On the right, a second oneM2M server on Amazon, which receives whatever traffic gets offloaded.''}
\tip{The figure is busy. Point at regions with your hand rather than reading labels. The next slide redraws it simply.}

\slide{layers}{$\sim$35 s}{Simplified redraw: device layer, edge layer with the Autonomic QoS Manager (M-A-P-E-K), cloud layer; orange arrow $\alpha$.}
\say{``Here is the same thing in three layers. Devices at the top send requests. The edge layer runs Mobius, and next to it the Autonomic QoS Manager, the M-A-P-E-K loop. The cloud layer is another Mobius on AWS.''}
\say{``The key point: the only thing the system decides is this orange arrow, alpha. One minus alpha of the traffic stays at the edge, alpha goes to the cloud.''}

\slide{edgecloud}{$\sim$30 s}{Table comparing edge and cloud: where, strength, weakness, best for, what was used.}
\say{``Why not just use one or the other? The edge is close and has no bill, but it is small and saturates under bursts. The cloud has plenty of capacity, but adds latency and charges per hour.''}
\say{``So the goal is to use the edge as much as possible, and the cloud only as much as needed. In the paper the edge is a 4-core Ubuntu box and the cloud is an AWS t2.medium.''}

\slide{workflow}{$\sim$40 s}{Workflow (redraw of paper Fig.\,2). Top row: data path. Bottom row: control loop, Monitor $\rightarrow$ Analyzer $\rightarrow$ Planner+FLC $\rightarrow$ Executor $\rightarrow$ decision.}
\say{``This is the step-by-step flow, the paper's Figure 2. Along the top, a reading travels from the device, through the injectors, into the oneM2M platform, into an application's container, and its performance numbers, CPU, RAM, RTT, success, land in a database.''}
\say{``Along the bottom, the control loop reads that database. Monitor collects, Analyzer cleans, the Planner with the fuzzy controller decides, the Executor acts, and the decision goes back up to re-route alpha of the traffic. The knowledge base feeds all of them.''}

\slide{mapek}{$\sim$45 s}{The MAPE-K circle with Knowledge in the middle; descriptions of each stage on the right.}
\say{``MAPE-K is a standard pattern for self-managing systems, originally from IBM's autonomic computing work. One turn of this loop runs every 5 seconds.''}
\say{``Monitor gathers CPU, RAM, round-trip time, queue length and bandwidth. Analyze normalises them and spots overload coming. Plan is where the fuzzy controller turns the state into alpha. Execute re-routes that share of traffic to the cloud. Knowledge stores the rules, policies and history, so later cycles can learn from earlier ones.''}
\ifasked{Does the Knowledge base actually learn?}{In this paper it stores rules and history, but the rules are fixed during the experiments. Learning the rules is listed as future work.}

\slide{handoff2}{$\sim$15 s}{Measured state $\rightarrow$ ``?'' box $\rightarrow$ one number $\alpha$.}
\say{``So: three numbers come in, one number comes out. Everything I've shown is plumbing. The interesting question is how alpha is chosen. Ashutosh?''}

\section*{If you get questions during Q\&A}
\ifasked{Why put the controller inside oneM2M instead of in a separate load balancer?}{Then any oneM2M application gets the QoS behaviour without changes, and the controller can see oneM2M-level metrics directly. The paper claims it is the only surveyed approach that does this end to end.}
\ifasked{How does the offloaded traffic reach the cloud?}{Over the oneM2M CSE-to-CSE link (Mcc) to a second Mobius instance on AWS; the Executor changes the routing.}
\ifasked{Why 5 seconds?}{Fast enough to follow bursts, slow enough that analysis costs under 3\,\% of one CPU core. Ashutosh has the configuration slide.}
